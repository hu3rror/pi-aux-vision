# Structured result for codemode scripts: outputSchema + structuredContent on describe_image

`describe_image` returns its full result — the transcription base (ADR-0002) plus the answer — as free text, and every byte enters the session model's context. Pi 1.0.0's `codemode` tool lets a script call tools in parallel and keep everything but the script's output out of the model's context, but a script calling `describe_image` had no structured view: it could only receive the raw text and had to parse success, failure, truncation, and usage out of prose. The tool now declares an `outputSchema`, so codemode scripts receive `structuredContent` — `{ ok, model, usage, transcription, truncated, resize_note? }` on success, `{ ok: false, error }` on expected failure — instead of the text. This is a pure addition: `content` and `details` are byte-for-byte unchanged, expected failures still return rather than throw and never set `isError` (ADR-0001), and exposure stays `direct` under the existing gating (ADR-0004), so sessions without codemode enabled observe zero change.

**Considered Options**:

- No `outputSchema` (status quo): the extension changes nothing; scripts receive the raw text and parse it themselves. Cheapest, but success/failure/truncation/usage decisions rest on text parsing, which is fragile, and the transcription base lands in script output unless the script author manually trims it.
- Minimal schema (chosen): `structuredContent` carries reliable programmatic metadata (`ok`, `model`, `usage`, `truncated`, `resize_note`) plus the full transcription as a plain string field. Scripts can `Promise.allSettled` a batch, filter by `ok`/`truncated`/`error`, and drop the transcription before returning a summary. The transcription is deliberately not split into `image_type`/`answer`/`attestation` fields: that would require parsing the vision model's free text, which is fragile and buys little. The transcription appears in both `content` and `structuredContent`; it never reaches the session model's context (scripts see it, direct calls read `content`), so the cost is session-file bytes only.
- Fully-structured schema: parse the transcription into discrete fields. Rejected: depends on the vision model's output format, which is not a contract we control.
- Change exposure to `codemode`/`model-only` so the tool hides from the main model: rejected — it would regress the direct-call path for blind session models and contradict ADR-0004. `direct` + active already makes the tool callable from scripts; no exposure change is needed.

**Consequences**: codemode scripts can batch and filter `describe_image` calls and keep large transcriptions out of the model's context. The contract is pinned in two places — the TypeBox `outputSchema` declared on the tool and the typed `DescribeImageResult` — and a consistency test asserts the runtime `structuredContent` validates against the schema, so declaration and implementation cannot drift. `usage` is exposed as a JSON-safe shape (the SDK constrains `structuredContent` to `JsonValue`); the schema promises only `totalTokens`, since provider usage shapes vary. Sessions without codemode enabled see no change: the tool, its gating, its error contract, and the footer are untouched. Compatibility baseline moved from pi 0.86.0 to 1.0.0 (the SDK this repo type-checks against), where `outputSchema` and codemode exist.
